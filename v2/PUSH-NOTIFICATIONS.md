# أَدِيب على الجوّال: التثبيتُ والإشعارات

> بُني في ٢٠٢٦-١٠-٠٣. الموقعُ يُثبَّت تطبيقًا على الشاشة الرئيسيّة (PWA)، وتصل إشعاراتُه شاشةَ
> القفل كأيّ تطبيق (Web Push). هذا الملفُّ بابُه البشريّ.

## ١. القاعدةُ التي يقوم عليها كلُّه

**آيفون لا يعطي الإشعارات إلّا لتطبيقٍ مثبَّت** (iOS 16.4+، من سفاري أو كروم: مشاركة ←
«إضافة إلى الشاشة الرئيسيّة»). وأندرويد والحاسوب يعطيانها في المتصفّح نفسه. فالواجهةُ تسأل
أوّلًا: أيُّ جهاز؟ ومن أين فُتح؟ ثمّ تعرض خطوات التثبيت أو زرّ التفعيل.

**والإشعارُ يتبع الجلسة لا الحساب وحده.** كلُّ اشتراكٍ صفٌّ يحمل معرّفَ الجلسة التي اشترك
منها، فمن خرج من الجهاز لا يصله بعدها ما يخصّه: `push_targets` تكنس الصفَّ الذي ماتت جلستُه
قبل كلّ إرسال. ومن دخل الجهازَ بعده يُعاد ربطُه تلقائيًّا (`PwaRegister`).

> وتنبيه: `signOut()` في الموقع عالميٌّ (يُنهي جلساتِ الحساب كلَّها)، فخروجٌ من جهازٍ واحد يوقف
> إشعاراتِ كلّ أجهزته حتّى يُفتح التطبيقُ عليها بجلسةٍ جديدة فيُعاد الربط.

## ٢. الأجزاء

| الجزء | الموضع |
|---|---|
| البيان (الاسم، البداية `/dashboard`، الألوان، الأيقونات) | `apps/web/src/app/manifest.ts` |
| الأيقونات (تُولَّد من `app/icon.svg`) | `public/pwa/*` ← `node scripts/pwa-icons.mjs` |
| عاملُ الخدمة (إشعاراتٌ فقط، لا تخبئة) | `public/sw.js` |
| جسرُ عامل النسخة الأولى (`importScripts("/sw.js")`) | `public/service-worker.js` |
| التشفير وتوقيع VAPID (بلا مكتبة، مُحاكَمٌ إلى RFC 8291) | `lib/push/webpush.ts` + اختباره |
| **بابُ الإرسال الواحد** | `lib/push/send.ts` ← `pushToUsers(userIds, message)` |
| الاشتراك والإيقاف والتجربة | `app/_pwa/actions.ts` |
| حالُ الجهاز (منطقٌ بلا رسم) | `app/_pwa/usePwa.ts` |
| ما يُقال في كلّ مرحلة | `app/_pwa/PwaContent.tsx` |
| الجدول والدالّة | `supabase/migrations/20261003034539_push_01_subscriptions.sql` |
| البطاقة الدائمة (الحساب وإعدادات اللوحة) والنافذة مرّةً على الجوّال | `app/_pwa/PwaCard.tsx` · `PwaIntro.tsx` |
| **رابطُ الإعلان العامّ** (آيفون: الخطوات · أندرويد: التثبيت · الحاسوب: رمزٌ يُمسح) | `/app` |
| المعرض بكلّ المراحل | `/ui/app-install` |

## ٣. الإرسالُ من أيّ حدث

```ts
import { pushToUsers } from "@/lib/push/send";

await pushToUsers([volunteerId], {
  title: "قُبل طلبُك التطوّعيّ",
  body: "فرصة «…» في انتظارك يوم الخميس.",
  url: "/me",            // مسارٌ داخليٌّ يُفتح عند النقر (غيرُه يصير «/»)
  tag: "volunteer-123",  // اختياريّ: الأحدثُ بالوسم نفسِه يحلّ محلَّ سابقه
});
```

- **لا يفشل الحدثُ بفشل الإشعار.** غيابُ المفاتيح يرجع `unconfigured`، والأجهزةُ الميّتة
  (٤٠٤/٤١٠) تُحذف، وما سواها يُعدّ ويُترك.
- **كلُّ دفعةٍ تُظهر إشعارًا.** آيفون يُسقط الاشتراكَ إن وصلته دفعةٌ صامتة.
- الحمولةُ دون ٣٨٠٠ بايت (سقفُ خدمات الدفع ٤٠٩٦ مع رأس التشفير).

## ٤. الإعداد

ثلاثةُ متغيّرات (`.env.example`): `NEXT_PUBLIC_VAPID_PUBLIC_KEY` و`VAPID_PRIVATE_KEY` و`VAPID_SUBJECT`.
تُولَّد **مرّةً للموقع** ولا تُبدَّل: تبديلُها يُسقط كلَّ اشتراكٍ قائم. والعامُّ منها يُدمَج في
حزمة المتصفّح وقت البناء، فيُضبط في Vercel **قبل** النشر.

## ٥. ما لم يُبنَ بعد

- **أيُّ الأحداث تُرسل** — قرارُ المالك. البنيةُ جاهزةٌ ولا حدثَ موصولٌ بها بعد.
- **رقمٌ فوق الأيقونة** (Badging API): يحتاج عدًّا لغير المقروء، ولا مركزَ إشعاراتٍ في الموقع بعد.
- جدولُ `notifications` (إشعاراتُ الانتخابات داخل القاعدة) لا يُرسَل منه دفعٌ بعد: القاعدةُ
  بلا `pg_net`، فجسرُه يحتاج قرارًا (امتدادٌ أو مهمّةٌ مجدولة).
